## init

O `init` inicializa a configuração e as dependências de um projeto existente, ou cria um projeto novo com `--name`. Ele instala as dependências, adiciona o util `cn` e configura as CSS variables do projeto.

```bash
npx shadcn@latest init
```

| Flag                                     | O que faz                                                           |
| ---------------------------------------- | ------------------------------------------------------------------- |
| `-t, --template`                         | O template a usar (next, vite, start, react-router, laravel, astro) |
| `-b, --base`                             | A biblioteca de componentes (base, radix, aria)                     |
| `-p, --preset [name]`                    | Usa uma configuração de preset                                      |
| `-y, --yes`                              | Pula o prompt de confirmação (padrão: true)                         |
| `-d, --defaults`                         | Usa a configuração padrão: `--template=next --preset=nova`          |
| `-f, --force`                            | Força a sobrescrita da configuração existente                       |
| `-c, --cwd`                              | O working directory (padrão: o diretório atual)                     |
| `-n, --name`                             | O nome do projeto novo                                              |
| `-s, --silent`                           | Silencia a saída                                                    |
| `--css-variables` / `--no-css-variables` | Usa (ou não) CSS variables para theming (padrão: true)              |
| `--monorepo` / `--no-monorepo`           | Cria a estrutura de monorepo / pula a pergunta de monorepo          |
| `--rtl` / `--no-rtl`                     | Habilita / desabilita suporte a RTL                                 |
| `--pointer` / `--no-pointer`             | Habilita / desabilita o cursor de pointer nos botões                |
| `--reinstall` / `--no-reinstall`         | Reinstala / não reinstala os componentes de UI existentes           |

O comando `create` é um **alias** do `init`.

## add

O `add` adiciona componentes e dependências ao projeto.

| Flag              | O que faz                                            |
| ----------------- | ---------------------------------------------------- |
| `-y, --yes`       | Pula o prompt de confirmação                         |
| `-o, --overwrite` | Sobrescreve arquivos existentes                      |
| `-c, --cwd`       | O working directory                                  |
| `-a, --all`       | Adiciona todos os componentes disponíveis            |
| `-p, --path`      | O caminho onde o componente será adicionado          |
| `-s, --silent`    | Silencia a saída                                     |
| `--dry-run`       | Mostra um preview das mudanças sem escrever arquivos |
| `--diff [path]`   | Mostra o diff de um arquivo                          |
| `--view [path]`   | Mostra o conteúdo do arquivo                         |

## apply

O `apply` aplica um **preset** em um projeto existente. Dá para aplicar só o theme ou só as fonts, sem reinstalar os componentes de UI:

```bash
npx shadcn@latest apply a2r6bw --only theme
```

Os valores aceitos em `--only` são `theme` e `font`.

## preset

O `preset` inspeciona códigos de preset e resolve o preset de um projeto existente.

- **`preset decode`**: decodifica um código de preset (`--json` para saída em JSON).
- **`preset resolve`**: resolve o preset a partir do projeto atual. O `preset info` é alias dele.
- **`preset url`**: imprime a URL de criação (_create URL_) de um código de preset.
- **`preset open`**: abre um código de preset no navegador.

## view

O `view` mostra itens do **registry** antes de instalá-los. Dá para ver vários de uma vez (`view button card dialog`) ou de registries com namespace (`view @acme/auth @v0/dashboard`).

## search

O `search` busca itens nos registries. O `list` é alias dele.

| Flag           | O que faz                                           |
| -------------- | --------------------------------------------------- |
| `-q, --query`  | A string de busca                                   |
| `-l, --limit`  | Máximo de itens exibidos por registry (padrão: 100) |
| `-o, --offset` | Quantidade de itens a pular (padrão: 0)             |

Os nomes dos registries precisam do prefixo `@`.

## build

O `build` gera os arquivos JSON do registry. Ele lê o `registry.json` e gera os JSONs na pasta `public/r`. Para mudar o destino, use `--output`.

## docs

O `docs` busca a documentação e as referências de API dos componentes. Com `-b, --base` você escolhe a base (base, radix ou aria); por padrão usa a do projeto.

## info

O `info` mostra informações sobre o projeto (`--json` para saída em JSON).

## migrate

O `migrate` roda **migrations** no projeto.

| Migration    | O que faz                                                  |
| ------------ | ---------------------------------------------------------- |
| `cn`         | Migra `clsx` e `tailwind-merge` para o `cn`                |
| `icons`      | Migra os componentes de UI para outra biblioteca de ícones |
| `base-color` | Migra o tema para outra base color                         |
| `radix`      | Migra para o `radix-ui`                                    |
| `rtl`        | Migra os componentes para suportar RTL (right-to-left)     |

Flags úteis: `-l, --list` (lista as migrations), `-f, --from` e `-t, --to` (origem e destino da base color ou da biblioteca de ícones).

### migrate cn

A migration `cn` troca `clsx`, `tailwind-merge` e `cnfast` pelo [`cn`](https://github.com/shadcn-ui/cn). Diferente das outras, ela **não exige** `components.json`. Funciona em qualquer projeto JS/TS com Tailwind CSS v4.

Ela vai:

1. Reescrever os imports de `clsx`, `clsx/lite`, `tailwind-merge` e `cnfast`.
2. Trocar as composições `twMerge(clsx(...))` por chamadas diretas de `cn(...)`.
3. Trocar o utilitário padrão do shadcn por um **re-export** direto.
4. Instalar o `cn` e remover os pacotes antigos quando não sobrar nenhuma referência.

A migration também preserva as APIs separadas quando são usadas de forma independente. As APIs de configuração customizada vão para `cn/config`.

> **Atenção:** o merge engine do `cn` suporta Tailwind CSS v4, como o `tailwind-merge` v3. Projetos com Tailwind v3 devem continuar no `tailwind-merge` v2. Uma migration só de `clsx` é segura em projeto com Tailwind v3.

Dá para migrar arquivos específicos passando um arquivo, diretório ou **glob pattern**. Migrations com escopo instalam o `cn`, mas mantêm `clsx`, `tailwind-merge` e `cnfast` no `package.json`, porque arquivos fora do caminho escolhido ainda podem usá-los.

O comando deixa imports não suportados como estão e os reporta para revisão manual (`experimentalParseClassName`, namespace imports, dynamic imports, chamadas diretas de `validators` e chamadas variádicas de `createTailwindMerge`). Uma dependência antiga é mantida enquanto sobrar alguma referência.

### migrate icons

Move os componentes de uma biblioteca de ícones para outra. Ele pergunta a origem e o destino, reescreve os imports e o JSX dos ícones na pasta `ui`, instala a biblioteca de destino e atualiza o `iconLibrary` no `components.json`.

Bibliotecas suportadas: `lucide`, `tabler`, `hugeicons`, `phosphor`, `remixicon` e `radix` (legacy).

- **Non-interactive:** use `--from` e `--to` para pular os prompts.
- **Escopo:** execuções com escopo (arquivo ou glob) **não** atualizam o `components.json`.
- Ícones sem equivalente na biblioteca de destino ficam intactos e são reportados no final.

### migrate base-color

Troca o tema de uma base color para outra. Reescreve as CSS variables do tema e atualiza o `baseColor` no `components.json`.

Base colors suportadas: `neutral`, `zinc`, `stone`, `mauve`, `olive`, `mist` e `taupe`.

- **Non-interactive:** `--to` migra a partir do `baseColor` atual do `components.json`, ou passe `--from` e `--to` explicitamente.
- Tokens que não batem mais com a base color de origem ficam intactos e são reportados no final.

### migrate rtl

Transforma os componentes para suportar idiomas RTL (da direita para a esquerda). Ele vai:

1. Atualizar o `components.json` com `rtl: true`.
2. Transformar propriedades CSS físicas em **logical properties** (ex.: `ml-4` → `ms-4`, `text-left` → `text-start`).
3. Adicionar variants `rtl:` quando necessário (ex.: `space-x-4` → `space-x-4 rtl:space-x-reverse`).

Sem caminho informado, ele transforma todos os arquivos da pasta `ui`.

### migrate radix

Atualiza os imports dos pacotes individuais `@radix-ui/react-*` para o pacote unificado `radix-ui`. Ele transforma os imports e adiciona o `radix-ui` no `package.json`. Depois você pode remover os `@radix-ui/react-*` que sobraram.

## eject

Quando você roda `init`, o shadcn adiciona `@import "shadcn/tailwind.css"` ao CSS global. Esse import traz utilities compartilhadas do Tailwind v4, como custom variants (`data-open:`, `data-closed:`) e animações de accordion.

O `eject` faz **inline** do `shadcn/tailwind.css` no CSS global e remove a dependência `shadcn` do projeto.

> **Atenção: essa ação é irreversível.** Depois do eject, atualizações futuras do CLI no `shadcn/tailwind.css` não se aplicam mais automaticamente.

Em **monorepo**, rode o comando a partir do workspace que contém o `components.json` e o CSS global (`eject -c packages/ui`).

## Dicionário rápido

| Termo           | O que é na prática                                                      |
| --------------- | ----------------------------------------------------------------------- |
| CLI             | Command Line Interface, a ferramenta que você usa pelo terminal         |
| preset          | Configuração de tema pronta, identificada por um código (ex.: `a2r6bw`) |
| registry        | O "catálogo" onde ficam os componentes disponíveis para instalar        |
| alias           | Outro nome para o mesmo comando (`create` = `init`)                     |
| migration       | Script que converte o projeto de um padrão para outro                   |
| dry-run         | Simula o comando e mostra o que mudaria, sem alterar nada               |
| diff            | Comparação entre a versão atual e a nova de um arquivo                  |
| glob pattern    | Padrão com curinga para pegar vários arquivos (`"src/**/*.tsx"`)        |
| scoped          | Limitado a um escopo (arquivo ou pasta), não ao projeto todo            |
| monorepo        | Um repositório com vários projetos/pacotes dentro                       |
| cwd             | Current working directory, a pasta onde o comando roda                  |
| RTL             | Right-to-left, idiomas como árabe e hebraico                            |
| eject           | "Sair" da dependência e trazer o código para dentro do seu projeto      |
| re-export       | Exportar algo que veio de outro módulo                                  |
| non-interactive | Roda sem fazer perguntas no terminal, bom para scripts e CI             |

## Pontos de atenção

- `npx shadcn@latest` baixa e roda a última versão do CLI sem instalar globalmente. É o jeito padrão de usar.
- `--yes` pula confirmações. No `add` com `--overwrite`, ele pode **sobrescrever arquivos que você customizou**. Rode o `--dry-run` primeiro.
- Os pares de flag `--x` / `--no-x` são o padrão para ligar e desligar uma opção.
- Antes de migrar para o `cn`, confira se o projeto está no **Tailwind v4**.
